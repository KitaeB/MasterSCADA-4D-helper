# Excel to SQL Parser

Консольная утилита на C++ для парсинга данных из Excel-файлов (таблиц сигналов, объектов и сообщений) и автоматической генерации SQL-скриптов (`create.sql`) для базы данных PostgreSQL.

Программа считывает настройки из файла `config.json`, открывает указанный Excel-документ, извлекает данные с заданных листов и формирует SQL-запросы `INSERT ... ON CONFLICT DO UPDATE` для таблиц `object_table` и `message_table`.

## Особенности
* **Гибкая настройка:** Все параметры (имена листов, стартовые строки, номера колонок) задаются через внешний файл `config.json`.
* **Поддержка UTF-8:** Корректное отображение кириллицы в консоли Windows.
* **Транзакционность:** Сгенерированный SQL-скрипт обернут в блок `BEGIN; ... COMMIT;`.
* **Безопасность данных:** Автоматическое экранирование одинарных кавычек для PostgreSQL, обработка пустых и некорректных ячеек.
* **Умный импорт:** При конфликте ключей в БД (по `struct_id` и `object_id`/`message_id`) записи обновляются, а не дублируются.

## Зависимости (Dependencies)

Для сборки проекта потребуются следующие библиотеки:
1. **[OpenXLSX](https://github.com/troldal/OpenXLSX):** Для чтения файлов формата `.xlsx` / `.xlsm`.
2. **[nlohmann/json](https://github.com/nlohmann/json):** Для парсинга конфигурационного файла `.json`.
3. **Компилятор C++:** С поддержкой стандарта C++17 (используются structured bindings и другие современные фичи).

## Структура проекта

* `main.cpp` — Точка входа, чтение конфига, открытие потоков и общая логика.
* `Parser.hpp` / `parser.cpp` — Логика обхода строк в Excel и генерации SQL-запросов (функции `parseObjects` и `parseMessages`).
* `Utils.hpp` / `utils.cpp` — Вспомогательные функции (экранирование SQL, безопасное извлечение чисел/строк из ячеек).
* `config.json` — Файл конфигурации.

## Конфигурация (`config.json`)

Файл конфигурации управляет тем, как именно парсер будет читать Excel-файл.

```json
{
    "path": "Таблица сигналов_v1.xlsm", 
    "node_id": 0,
    "node_name": "СИКНП",
    "object": {
        "DI": {
            "sheet": "DI",                 // Имя листа в Excel
            "start_row": 2,                // Строка, с которой начинаются данные
            "has_tech": true,              // Есть ли колонка технологической позиции (иначе дублирует имя)
            "struct_id": 5,                // Идентификатор структуры для БД
            "object_id_column": 6,         // Номер колонки с ID объекта
            "tech_name_column": 2,         // Номер колонки с технологическим именем
            "name_column": 3               // Номер колонки с названием
        }
        // ... другие типы (AI, DO, AO, Protect и т.д.)
    },
    "histor_sheet": "Histor",              // Имя листа с историей/сообщениями
    "histor_row": 15                       // Стартовая строка для чтения сообщений
}
```

**Примечание:** Если путь к Excel-файлу (`path`) не указан или пуст, программа попросит ввести его вручную в консоли.

## Использование

1. Поместите файл `config.json` в папку с исполняемым файлом (или передайте путь к нему первым аргументом командной строки).
2. Запустите программу:
   ```bash
   ./excel_parser
   # или с указанием пути к конфигу:
   ./excel_parser /path/to/my_config.json
   ```
3. Программа начнет вывод в консоль о процессе парсинга листов.
4. После успешного завершения в директории появится файл `create.sql`.

## Результат работы (`create.sql`)

Утилита генерирует файл со скриптами вставки. Пример содержимого:

```sql
BEGIN;

INSERT INTO public.object_table (struct_id, object_id, object_tech, object_name, nodeid, nodename) VALUES (...)
ON CONFLICT (struct_id, object_id) DO UPDATE SET ...;

INSERT INTO public.message_table (struct_id, message_id, priority, message) VALUES (...)
ON CONFLICT (struct_id, message_id) DO UPDATE SET ...;

COMMIT;
```
Этот скрипт можно напрямую выполнить в вашей СУБД PostgreSQL.
